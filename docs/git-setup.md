# 产品经理 Git 配置指引（一次配置，终身无感）

> 适用：本团队产品经理，macOS + 任意 AI 编码工具。全程约 3 分钟，配完以后你只需要对 AI 说「提交并推送」，git 的一切由 AI 代跑。
>
> **只想快点装完**：直接照 [QUICKSTART.md](../QUICKSTART.md) 第一步那段话发给 AI，它会把 git 配置连同 node / openspec 一起装好。本文是这件事的详细说明 + 管理员加人指引。

> **本文按你们产品仓所在的平台走。** 两个平台的差别只在第 2 步拿凭据，其余一样。

## 第 1 步 · 注册并接受邀请（1 分钟）

1. 注册托管平台账号（用公司邮箱）
2. 把用户名发给仓库管理员，等待邀请进产品仓（角色：**开发者 / Write**）

## 第 2 步 · 拿到访问凭据（1 分钟）

### 仓在 GitHub —— 用 `gh`，不用手动搞令牌

```bash
brew install gh
gh auth login        # 选 GitHub.com → HTTPS → 用浏览器登录，点一下就好
```

`gh auth login` 会顺手把 git 的凭据助手也配好，之后 push / pull 都不再要密码。**GitHub 上这条比手动生成令牌省事**（GitHub 也支持手动令牌，想用照 Gitee 那节的思路配即可）。

### 仓在 Gitee —— 生成私人令牌

Gitee 网页右上角头像 → **设置** → 安全设置 → **私人令牌** → 生成新令牌：

- 描述随意（如「本机 mac」）
- 权限只勾 **projects**
- 点生成，**复制令牌**（只显示一次）

## 第 3 步 · 对 AI 说一句话（1 分钟）

打开 Claude Code / Cursor，把下面这段话补全后发给 AI：

> 帮我配置 git：姓名「你的中文名」，邮箱「你的公司邮箱」，平台用户名「xxx」；
> 仓在 Gitee 的话把私人令牌「粘贴令牌」存进 macOS 钥匙串，仓在 GitHub 的话我已经跑过 gh auth login 了；
> 然后把 <你们产品仓的地址> 克隆到 ~/repos/

AI 会完成：`git config` 身份设置 → 令牌写入 macOS 钥匙串（此后推拉不再要密码）→ 克隆仓库。

## 配置完成后的日常（你只需要这三句话）

| 场景 | 对 AI 说 |
|---|---|
| 开始工作前 | 「拉一下需求仓最新」 |
| 改完需求文档 | 「提交并推送，说明：xxx」 |
| 有冲突/报错 | 把报错发给 AI，让它处理 |

## 安全须知

- 令牌等同密码：只粘贴给你**本机**的 AI 会话用于写入钥匙串，不要发到群里、不要存在文档里
- 换电脑 / 疑似泄露：到平台的令牌页**删除旧令牌**再生成新的（GitHub 用 `gh auth logout` 后重新 login），重做第 3 步即可
- 每人用自己的账号——commit 记录就是工作留痕，别用同事的凭证

## 管理员侧 · 怎么把人加进来

> 本仓是**私有仓**，没被加成员的人连 clone 都不行。上面第 1 步说的「等待邀请」，等的就是这一步。

**加人前先要到对方的平台用户名**（不是昵称、不是邮箱，私有仓靠它精确邀请）。

1. 打开产品仓的网页
2. 顶部菜单 → **管理**
3. 左侧 → **仓库成员管理**
4. **邀请用户** → 输入平台用户名 → 权限选 **开发者 / Write** → 确认
5. 对方在站内信 / 邮件里点接受，然后照本文前三步配置

**权限一律给「开发者」**，产品、研发、还在培训的新人都一样。原因见 `openspec/conventions/collaboration-convention.md` 第六节——观察者不能 push，而上手流程最后一步就是 push，卡在那里的人只会以为工具坏了。

| 角色 | 能做 | 不能做 |
|---|---|---|
| 观察者 / Read | clone / pull、提 Issue 与 PR | **push** |
| **开发者 / Write**（都给这个） | push 到非保护分支 | 改仓库设置、管理成员 |
| 管理员 | 改设置、加人 | — |

> 若仓库属于**组织**账号，左侧还会有「组织成员 / 团队」入口。人多时更省事的做法：建一个「产品」团队整体授权成开发者，之后进人只拉进团队，不用逐个仓库配。

**离职 / 转岗**：同一页面移除成员即可。他本机的令牌会立即失效，已提交的内容保留在 git 历史里，不受影响。
