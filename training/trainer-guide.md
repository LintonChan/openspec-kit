# 讲师手册 · 怎么带一场 openspec 培训

> 给带培训的人看的。学员看 [QUICKSTART.md](../QUICKSTART.md) 就够了。

## 时长与形式

**2 小时，人手一台电脑，边讲边跑。** 不要做成 PPT 宣讲——这套东西的价值全在"跑一遍撞上坑"，听是听不会的。

学员用自己惯用的 AI 工具（Cursor / Codex / Claude Code 都行）。**故意不统一工具**——不同工具的坑不一样，正好当场暴露。

---

## 教学素材：kit 自带的玩具需求

`openspec/requirements.md` 里装的是「团队会议室预订」，4 个需求点。

**它是故意留了洞的**，每个洞对应一条流程铁律：

| 需求点 | 故意留的洞 | 应该撞出什么 |
|---|---|---|
| A1-1 预订记录列表 | 没写全「列表五要素」 | AI 应把缺的要素列成评审待定项来问你 |
| A1-2 新建预订 | 「会议主题」没定字符数上限 | AI 应追问上限是多少、**按字符还是按字节** |
| A1-3 取消预订 | 没写要不要二次确认 | 画原型时闭环审计应撞出这个断点 |
| A1-4 我的预订 | 没写与 A1-1 是一个页面还是两个 | AI 应问清楚，而不是自己拍 |

**这四个洞就是整场培训的考点。** AI 没问出来，说明流程没走对——当场就能演示"为什么规则要写进 AGENTS.md 而不是靠人记"。

> ⚠️ 别让学员觉得玩具需求写得烂。**它是故意烂的**，开场就要说清楚，否则学员会把注意力花在"这需求写得不对"上。

---

## 两小时怎么排

| 时间 | 内容 | 要点 |
|---|---|---|
| 0:00–0:15 | 装环境 | `node -v` → `npm i -g @fission-ai/openspec` → 配 git 凭据 → clone。**提前发链接让大家先装好**，否则这步能吃掉半小时 |
| 0:15–0:30 | 讲三层结构 + 三个停点 | 只讲这两件事。别讲 OpenSpec 是什么，跑完自然懂 |
| 0:30–1:00 | **跑 propose** | 让学员自己描述会议室需求给 AI。**盯住：AI 有没有列出评审待定项、有没有问字符上限** |
| 1:00–1:10 | 对齐待定项 | 现场拍板：主题 40 字符（按字符）、取消要二次确认、A1-4 是筛选不是独立页 |
| 1:10–1:40 | **出原型** | 盯住三条验收判据。Codex 用户大概率会翻车，这是最好的教学时刻 |
| 1:40–1:55 | 评审闭环 | 演示回写两处（requirements + spec），讲清为什么缺一不可 |
| 1:55–2:00 | 收尾 | 讲 `git pull` / `git push` 两个日常动作，以及出问题查 AGENTS.md |

## 三个必须演示到的翻车现场

这三个是真实事故，**演示比讲有用十倍**。

### 1. AI 不问就开下一个包

**怎么触发**：让学员对 AI 说「按拆包方案把这几个包都做了」。

**会发生什么**：AI 一路做下去，每个包里都埋着没人评审过的决定。

**讲什么**：`opsx-propose` 自带一句 `prefer making reasonable decisions to keep momentum`——那是给"一个人写代码"设计的默认值。这里的产出物是需求事实源，研发直接照着实现。所以 [AGENTS.md](../AGENTS.md) 第一节**显式覆盖了这句**。

**让学员做**：把 AGENTS.md 第一节甩给 AI，看它退回来。

### 2. 原型是一张光秃秃的网页

**怎么触发**：让 Codex 用户直接说「画个原型」。

**会发生什么**：Codex 没有 skill 自动发现机制，`.codex/skills/` 对它就是一堆普通文件。它会手写一个普通 HTML——没有三段结构、没有 PRD 面板、没有样式注入。

**讲什么**：这就是为什么 AGENTS.md 第二节要用**显式路径**要求 AI 主动读 SKILL.md，而不是指望自动触发。

**让学员做**：用三条验收判据自查产物，然后让 AI 先读 SKILL.md 再重做，对比两次结果。

### 3. 只改了 spec，没回写需求列表

**怎么触发**：评审时改一条规则（比如把主题上限从 40 改成 20），看 AI 改了几处。

**讲什么**：需求列表是产品语言的事实源，spec 是开发验收依据。**只改一处必然漂移**，下一个读需求的人（含 AI）会读到已被推翻的旧结论并据此推导。

## 培训后：学员该拿到什么

- [ ] 本机装好 node + openspec CLI + git 凭据
- [ ] 知道三层结构（requirements → changes → specs）各自的事实源
- [ ] 知道三个停点在哪，AI 越过时会拦
- [ ] 知道原型的三条验收判据，能一眼看出 AI 有没有走 skill
- [ ] 知道出问题第一件事是查 [AGENTS.md](../AGENTS.md)

**不要求记住**：conventions 三份的细节、config.yaml 的结构、契约机制。用到时 AI 会遵守，人按需查。

## 学员之后在哪干活

**默认是进现有的产品仓单根共享，不是各起各的仓。**

只有当新产品线**完全不用现有底座**（账号 / 权限 / 后台 / 官网都不碰）时才起独立仓，用：

```bash
tools/init-new-repo.sh ~/repos/xxx-openspec "产品名"
```

判据见 [collaboration-convention.md](../openspec/conventions/collaboration-convention.md) 第一节。**判错的代价不对称**：本该单根却起了独立仓 → 底座漂移，几个月后要痛苦合仓；本该独立却挤进单根 → 只是有点吵，随时能拆。**拿不准选单根。**
